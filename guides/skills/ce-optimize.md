# ce-optimize：用同一把尺子决定要不要保留改动

编码结果已经正确，但处理一批离线消息比预期慢。输入大小、批量大小和测量口径不固定时，“更快了”没有可比性。

`/skill:ce-optimize 用固定的合成载荷比较当前编码器和候选实现：记录 Python 版本、批量大小、重复次数和总耗时。必须输出相同字节，不联网。先测基线再决定改哪里。`

给它能重跑的命令、目标指标和正确性测试。实验可能生成基准数据或修改候选代码，先约定落点；不要拿生产数据当默认样本。结束时看基线和候选是否在相同条件下比较、结果是否超出测量波动。没有稳定收益就保留原实现；如果已经确定要做的修改而不需比较，直接走实施。
