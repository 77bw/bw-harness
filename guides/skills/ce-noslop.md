# ce-noslop：把一句模糊的话改成别人能核对的话

计划写“显著优化算法性能”，但没有输入范围、基线和指标。“显著”读起来很肯定，却没有给测试者任何可执行的信息。这个内部写作 Skill 常由规划和文档审查调用，也可以只检查一小段。

`/skill:ce-noslop mode:edit 改写这句验收条件：“显著优化编码性能”。只使用已有事实：输入是固定合成载荷，指标为总耗时，目前没有基线。直接回在对话，不写文件。`

一种合格改写是：“对固定合成载荷测量编码总耗时，记录改动前后的结果。”它没有凭空发明提速百分比。需要先找问题而非改写时用 `mode:detect`；要改变功能范围或验收阈值，请回到计划决策，不要把它包装成润色。
