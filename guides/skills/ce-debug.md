# ce-debug：先分清是谁写错了长度

编码 `abc` 正常，换成「你」就报长度错误。可能是编码器写了字符数，也可能是解码器读错边界。此时有失败现象，还没有足够证据决定该改哪个函数。

```text
/skill:ce-debug 编码 abc 正常，编码「你」后解码失败。前缀约定为 UTF-8 字节数；请分别对照 03 e4 bd a0 检查编码和解码。先定位，不修改代码。
```

把原始错误、最小输入和复现入口给它。看它是否单独比较了 `encode("你")` 的字节，也用**预先写好的字节**喂给解码器。若两边都取编码器的输出作答案，一次往返成功仍分不清原因。

默认示例只诊断。确认因果链后才批准改动和回归；完成的证据是固定输入曾经失败、修复后通过，邻近正常用例也没有退化。[完整修复流程](../workflows/bug-fixing.md)
