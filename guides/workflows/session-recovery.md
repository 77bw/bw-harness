# 换会话后，从上次停下的地方继续

上次已实现消息编码，今天要补截断输入的回归。不要从“帮我看看整个仓库”开始。在**同一业务项目根目录**新开 Pi：

```text
/skill:bw-help 请按 AGENTS.md、GLOSSARY.md 和 docs/status.md 找到当前计划。对照实际源码和测试，告诉我哪一项还没完成；先只读，不重新规划。
```

1. 从 `status.md` 找**当前目标、计划位置和上次验证条件**，而不是把它当完整日志。读对应计划；只在与当前问题有关时打开 ADR、研究和经验。
2. 分清“上次通过”和“这次验证”。若 status 说已测截断，但源码已改，先看测试是否还覆盖那个分支。获准后在终端从项目根运行 `uv run pytest -q`，记录这一次的结果。
3. 若计划仍适用，继续一个未完成单元，不再创建同主题计划。若状态与工作树矛盾，先报告具体差异，再决定修测试还是修文档。

当下一位 Agent 无法访问当前会话、而必要背景又没进入项目文档时，用 [ce-handoff](../skills/ce-handoff.md) 给一份短交接。常规接续只需要现有项目文件，不需要把会话导出到仓库。
