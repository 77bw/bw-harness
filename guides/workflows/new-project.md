# 从空目录到第一个可验收的功能

先做[工作流接入](../quick-start.md)，不要为“接入完成”而生成根本用不到的模块。例：为仓库实现一个离线消息编码器。

1. 如果“长度”有歧义，输入 `/skill:grill-with-docs 明确消息长度指字节还是字符`。确认术语后继续同一会话；没有重大取舍不用建 ADR。
2. `/skill:ce-plan 为刚确认的编码契约写可实施计划：覆盖空串、多字节、越界和截断；不新增 Web 服务。` 检查实际计划路径和验收用例。已有同主题计划就从原位继续。
3. 选择实施该计划，或 `/skill:ce-work` 加上实际计划路径。按项目真实工具验证，保留逐单元提交及原生审查。已有可用远端时走[原生交付](git-delivery.md)；缺远端则如实报告本地结果。
4. 若暂停，明确告诉治理当前计划、完成单元与剩余验证，让新会话接着做。
