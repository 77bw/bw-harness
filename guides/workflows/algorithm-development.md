# 让一个算法候选通过独立验证，再放进 src

任务：一字节长度前缀后跟 UTF-8 载荷。容易犯的错是 `decode(encode(s)) == s` 通过就宣布正确——如果编解码两端都按字符数算，它们可能一起错。

| 阶段 | 在业务项目做什么 | 怎样判断可以继续 |
|---|---|---|
| 定预期 | 把独立推算的向量放 `tests/fixtures/vectors/`。例如空串 → `00`，「你」→ `03 e4 bd a0`。注明自造数据和适用格式。 | 不运行候选实现，也能解释每个预期字节。 |
| 做实验 | 临时想法放 `.local/scratch/`；值得重跑才写 `experiments/` 下的入口。让候选逐条对照向量。 | 别人在没有你个人 `.local` 数据的情况下能复现。 |
| 晋升 | 把稳定函数放 `src/`，测试直接导入正式包，继续使用同一组向量。 | 编码和解码分别验证；255/256 字节、截断、尾随数据都有明确结果。 |

在 Pi 可这样开始：`/skill:tdd 先用固定字节验证「你」的长度前缀；让测试因错误长度而失败，再改最小实现。` 在项目根运行 `uv run pytest -q`，再运行 `uv run python scripts/check_structure.py`。测试通过但 `src` 还在引用实验目录，仍不能算晋升完成。

将这次观察更新到已有 `docs/research/` 主题，注明向量和实现位置。修订历史交给 Git；只有同时支持两种不兼容格式时，才需要两套有独立覆盖的实现。
