# 接手已有项目：先弄清什么不能动

目录里已有 `app.py`、旧 `CONTEXT.md` 和一次性脚本 `probe_final.py`。不要清空目录，也不要把它当成新模板项目。先在该目录启动 Pi：

```text
/skill:setup-bw-harness migrate 只读扫描。列出当前入口、现有规则、旧术语和可疑临时文件，给我逐文件建议；不要安装、移动或补写任何东西。
```

**先拿到清单，不是整理后的目录。** 核对每个建议的原路径、目标、理由及回退方法。`CONTEXT.md` 可能同时有术语和进度，不能整份改名。`.local` 中的数据即使不进 Git，也可能是唯一证据。

**确定基线。** 选一条你知道可安全执行的现有测试或离线入口，记下命令、退出状态和输出。旧项目没有测试时就写明缺口；不要启动一个可能访问外部服务的脚本来凑结果。

**只批准一批。** 例如在确认某脚本确实临时且无人引用后，输入：`/skill:project-governance migrate 只批准将 probe_final.py 移到 .local/scratch/probe.py；app.py、旧文档和原始数据不动。重跑刚才的基线，报告差异。` 如果执行结果变化，先回退这一批并排查，不扩批。

只想补文档时用 setup 的 `docs` 模式先预览；明确同意后只新增缺项，已有文档走差异合并。完成标志是原入口仍可运行、唯一数据仍在、此次实际变更与批准清单相符，不是“一次消灭所有结构告警”。
