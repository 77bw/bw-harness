# 接手已有项目而不改它的架构

项目已有可执行的 app.py、旧 CONTEXT.md 和一份唯一实验样本。先在原目录运行 `/skill:setup-bw-harness check`，核对真实 Git 根、项目指令、文档根与验证入口。用项目已有的一条离线命令建立已知基线；无测试时记录缺口。

接入用 `/skill:setup-bw-harness 接入当前项目，保留宿主规则、代码和依赖`。已有 BW 规则要升级时用 `update`；它只处理可识别的旧规则，不因升级删除你维护的文件。完成标志是入口仍可用、同义规则没有重复、实际差异与预告一致。

**整理旧知识另走一次有范围的迁移。** `/skill:project-governance migrate 请先按段列出 CONTEXT.md 中的术语、进度和反例，给出目标、引用与可恢复出处。` 核对清单后可回复“只迁移已确认的术语和带向量证据的反例；进度与原样本保留”。检查旧引用、新权威文档和唯一材料。批准一批不等于批准全库清理。
