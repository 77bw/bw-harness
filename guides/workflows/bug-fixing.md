# 修 Bug：先用一个输入区分两种原因

现象：“abc”正常，“你”失败。是编码端写错长度，还是解码端读错边界？不要让 Agent 一次改两端。

在项目目录的 Pi 对话发：

```text
/skill:ce-debug 编码 abc 正常，中文「你」解码失败。协议规定前缀是 UTF-8 字节数。请分别对照固定字节 03 e4 bd a0 测试编码和解码，先定位，不改代码。
```

检查它返回的**实际值**。若编码结果以 `01` 开头，而解码固定向量成功，证据指向编码端；如果没有这种观察，就不能照这个假设修。这些字节是已知输入，不是从待测实现生成的答案。

定位后，明确批准最小修复和回归测试。在业务项目根运行 `uv run pytest -q`。原先的失败测试应从红变绿，已有用例不能退化；改了模块归属还要跑结构检查。简单修复不用另开计划。若这次揭示了两端一起犯错导致往返测试失效，再判断是否值得[沉淀经验](knowledge-compounding.md)。
