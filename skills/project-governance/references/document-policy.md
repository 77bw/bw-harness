# Decide where a fact belongs

Identify the question answered, not the filename. Resolve actual configured roots and follow the substantive rule file; the paths below name roles, not a required tree.

| Question | Authority and write condition |
|---|---|
| What must an agent do, and when should it read more? | One effective root instructions file: concise working agreements and pointers; follow any host include. Project-wide convention changes need review. Personal/global preferences are separate and require the user's explicit choice. |
| Where are domain, workflow and tracker rules? | agents/domain, workflow and optional tracker notes linked by the effective entry. Retain actual external tracker selection; CE owns the single plan's scope, units and acceptance. |
| What does a term mean? | GLOSSARY or the GLOSSARY-MAP-selected domain glossary. Reuse the established Matt format, avoided terms and relationships; merge synonyms, surface conflicting definitions. Historical CONTEXT/MAP and CONCEPTS are migration inputs, not co-authorities. |
| Why accept an important, difficult-to-reverse tradeoff? | An actual ADR in the relevant domain; capture context, alternatives, decision, consequences, and supersession if relevant. A routine implementation detail is not an ADR. |
| What was tested and under what conditions? | The existing research topic. One note can contain different claim states. Link a durable sanitized reproduction, test, revision or evidence index, not raw private data. |
| How do we prevent recurrence of a verified, corrected problem? | Native CE Compound decides form and updates existing knowledge where possible. A test or rule may suffice. CE solutions and refresh retain native format, discoverability and history. |
| What is happening and what is next? | Status is a current index to live plan, Git, checks and blockers; update in place. It does not replace execution receipts or become a dated diary. |
| What is the project/architecture or code standard? | Existing README/architecture notes describe verified code; native CODING_STANDARDS.md and REVIEW.md hold project standards/review criteria. Create or change only when needed and ground it in actual behavior. |
| What is just working material? | Existing protected raw assets, ignored .local or CE scratch, session artifacts. Protect unique evidence first. CE ideation, prototypes, handoff and other legitimate native artifacts are not violations merely because they are outside the example tree. |

When two records overlap, distinguish copies of **meaning** from helpful links. Keep the best-supported current owner, link to it from consumers, preserve provenance and historical decisions. If scope, authority or factual conflict cannot be resolved, record both positions as a question and the check/owner that could settle it. Never downgrade an existing user rule or change a global setting to satisfy a doc audit.
