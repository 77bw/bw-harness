# 决定事实所属的位置

确定所回答的问题，而不是文件名。解析实际配置的根并遵循实质性规则文件；下面的路径命名角色，而不是必需的树。

| 问题 | 权限及写入条件 |
|---|---|
| 代理必须做什么，什么时候应该阅读更多内容？ | 一份有效的根指令文件：简明的工作协议和指示；遵循任何主机包含。项目范围内的惯例变更需要审查。 Personal/global 偏好是独立的，需要用户明确选择。 |
| 域、工作流程和跟踪器规则在哪里？ | agents/domain，工作流程和可选跟踪注释由有效条目链接。保留实际的外部跟踪器选择； CE拥有单一计划的范围、单位和验收。 |
| 术语是什么意思？ | GLOSSARY 或GLOSSARY-MAP 选择的域术语表。重复使用既定的 Matt 格式，避免术语和关系；合并同义词，表面冲突的定义。历史CONTEXT/MAP和CONCEPTS是移民投入，而不是共同当局。 |
| 为什么要接受一个重要的、难以逆转的权衡？ | 相关域中实际的ADR；捕获背景、替代方案、决策、后果和替代（如果相关）。例行实施细节不是ADR。 |
| 测试了什么以及在什么条件下进行的？ | 现有的研究课题。一张注释可以包含不同的声明状态。链接持久的经过消毒的复制、测试、修订或证据索引，而不是原始私人数据。 |
| 我们如何防止已验证、已纠正的问题再次发生？ | Native CE 化合物决定形式并尽可能更新现有知识。测试或规则可能就足够了。 CE 解决方案和刷新保留了原始格式、可发现性和历史记录。 |
| 正在发生什么以及接下来会发生什么？ | 状态是实时计划、Git、检查和阻塞项的当前索引；更新到位。它不会取代执行收据或成为注明日期的日记。 |
| project/architecture或代码标准是什么？ | 现有的README/architecture注释描述了经过验证的代码；本地CODING_STANDARDS.md和REVIEW.md持有项目standards/review标准。仅在需要时创建或更改，并将其扎根于实际行为。 |
| 什么只是工作材料？ | 现有受保护的原始资产，忽略 .local 或 CE 暂存、会话产物。首先保护独特的证据。 CE 构思、原型、切换和其他合法的本地产物并不仅仅因为它们位于示例树之外而被视为违规。 |

当两条记录重叠时，区分**含义**的副本和有用的链接。保留最受支持的当前所有者，从消费者那里链接到它，保留出处和历史决策。如果范围、权威或事实冲突无法解决，请将这两个立场记录为问题，并记录可以解决问题的check/owner。切勿降级现有用户规则或更改全局设置来满足文档审核。
