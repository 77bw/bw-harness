# 研究主张和证据

找到对象或稳定主题的现有注释。将更改的声明合并到该注释中，保留被取代的条件；避免每次运行一个文件。确定object/version、相关配置、输入群体以及结果**不**涵盖的内容。链接跟踪的、合成的或编辑的证据参考和精确的check/command、测试向量 ID 或修订。分别说明离线集成、模拟集成和真实集成；仅靠绿色模拟并不能建立生产行为。

| 声明状态 | 最低限度的证据 |
|---|---|
| VERIFIED | 观察到的结果和可检查的来源或可重复的检查**在规定的条件下**；说出实际结果。 |
| HYPOTHESIS | 提出的解释加上下一个判别观察或实验。不要将其写成词汇表事实或已解决的学习。 |
| REFUTED | 具体counterexample/negative结果、方法以及排除索赔的条件。 |
| STALE | 之前的证据或修订以及哪些变化足以需要重新检查。保持旧的主张和限制易于理解。 |

历史标签是来源声明，而不是当前结果。如果旧报告说“反驳”，但其样本省略了证明反例所需的comparator/input，则保留并归因于该历史断言；将当前声明标记为HYPOTHESIS，等待缺少的歧视性证据，而不是给新记录一个REFUTED判决。

例如，使用合成数据：“REFUTED — 在模拟器 1.2 中，批次始终保留两个工人的输入顺序。Vector order-02 为 A,B 生成 B,A。这不会测试一个工人。”如果新版本更改了计划，请将新版本的扩展标记为 STALE 待重新运行，而不是追溯删除观察。如果私人原始证据无法公开，请将其保存在受控位置并标识经过消毒的复制品或描述 access/evidence 差距。
