# 烘焙计划中

当阶段 1.6 中的条件成立时，运行 `ce-bakeoff`：标准或深度持久计划，以及相应的研究如何开放，其替代方案需要开发，其逆转将代价高昂。明确的用户请求满足任何持久计划的条件。保留现有的output/depth重新分类规则。确定的产品方向并不能确定未指定的技术选择，但是用户、需求或已建立的代码库模式已经明确确定的方式不能重新开放以进行竞争。如果没有留下合格的决定，请说明原因并继续正常规划。已经足够具体以供比较的替代方案需要判断，而不是发展；在计划中保留这种比较或使用`ce-pov`。竞赛无法满足明确的预算或时间限制，或者用户说要选择一个，也排除了这种情况。

在研究之后并在修复该决策或依赖单元之前，使用 `references/reasoning-elevation.md` 中的激活解析规则来解析模型偏好。将已解决的偏好（包括明确的限制）传递给`ce-bakeoff`，并包含要求、问题、完整的研究证据、已确定的决策、项目限制、预算和方法草图保真度。明确的候选模型组合优先。 Bake-off 会派遣自己的新候选人并处理自己的后备事务；不要为每个面包师运行计划编写适配器。如果没有任何偏好，请允许 Bake-off 的默认模型系列探索。

烘焙涵盖从探索到选择的一切。将其完整返回到技术决策基本原理和依赖单元中，而无需更改稳定标识符或发明用户批准。保留incomplete/unresolved状态：如果它阻止了防御计划，则使用计划现有的阻止合同；否则披露缺失的比较并继续使用现有证据。仅等待用户偏好的返回成为计划中的开放决策；如果没有同步用户，请继续使用所公开的默认值，而不是停止运行。

现有的最终解释和作者高度仍然保持在正常水平。向作者提供完整的烘焙结果和来源。它采用了选定的方法并报告了重大矛盾证据，而不是默默地重新进行比赛。正常的信任、审查和移交规则仍然具有权威性。
