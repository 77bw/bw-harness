# BW 工作流导航

派生自 Matt Pocock 的 ask-matt，沿用 MIT 许可证。推荐某个 Skill 或建议跳过一步前，先读当前宿主实际加载的 `SKILL.md`。若分支由引用文件控制，也要阅读相应文件。指南只用于说明；同名的全局安装不代表当前分发包有此能力。

## 确定当前阶段

1. 区分技能说明、任务导航和明确要求执行下一步。没有仓库时直接回答问题，不为提供建议创建仓库。
2. 在项目中先读生效的项目规则、实际文档根和当前状态。只读已明确的当前计划及与本任务有关的代码、Git、ADR、研究、经验和运行证据。状态记录不等于实施计划或审查凭据。
3. 找出下一个待解决的决定或实施单元，再核对目标 Skill 的实际来源，读其正文和分支引用。遇到同名来源冲突或依赖缺失，指出具体问题，不擅自安装或替换。

**显式命令不等于自动发现。** Pi 的模型发现列表可能不显示仅供用户显式调用的入口，如 setup。缺席不代表未注册。可用 shell 时，用与本会话相同的项目目录、包配置、资源过滤和扩展设置查询 Pi 的只读命令目录：

```sh
printf '%s\n' '{"id":"bw","type":"get_commands"}' | pi --mode rpc --no-session
```

核对响应 `data.commands` 里的确切 `skill:<name>` 和 `sourceInfo.path`。CE 扩展注册到当前包也有效。路径匹配后给出用户可直接调用的命令；核对不了时，区分包内存在和实际注册尚未验证，指出如何通过宿主选择器核对。仅有相邻文件并不足以确认注册。咨询不触发写入式 setup。

## 从需求到交付

- 尚未接入：建议显式调用 `setup-bw-harness`。已有接入且需合并新规则，用其 `update`。
- 术语、范围或长期取舍不清：`grill-with-docs`。需要探索产品方向和方案：`ce-brainstorm`。选真正能解决歧义的分支，不重复访谈；尽量在同一会话把已定决定交给规划。
- 有正在进行的 CE 运行：遵循 `ce-work` 的恢复契约和实际运行状态。有现成实施计划：先读 [实施输入分类](../ce-work/references/input-triage.md)，把原计划路径交给 `ce-work`。只有需求草案：用 `ce-plan` 原位补全。同一任务不另建计划或票据。小改可直接实施并按项目真实入口验证。
- 交付走 CE 原生实施单元、验证、审查和发布，不默认使用 `mode:return-to-caller`。提交、推送与 PR、处理反馈和持续看护分别核对 `ce-commit`、`ce-commit-push-pr`、`ce-resolve-pr-feedback`、`ce-babysit-pr`。考虑实际远端、权限、用户未完成改动和本次范围。

## 其他分支

| 情况 | 入口和判断标准 |
|---|---|
| 可重复故障或原因未知 | `ce-debug`：先复现、确定根因，再核对回归证据。当前计划中的失败单元仍留在原计划。 |
| 算法或研究假设 | 先看已有主题与适用条件；采用独立测试向量、判定依据或可区分假设的实验。小实验直接做，行为验证可用 `tdd`，多阶段工作走 CE 规划和实施。不为数值结论创建用户体验原型。 |
| 必须真人试用交互或视觉效果才能决定 | 阅读 `ce-prototype` 的范围规则；以人的观察作决策，将结论回填原需求或计划。 |
| 领域建模或指定架构改善 | `domain-modeling` 处理术语与 ADR；`codebase-design` 讨论接口和模块边界；明确要求架构审视时用 `improve-codebase-architecture`。都不是强制重构。 |
| 已验证的修复纠正了错误认识；或现有经验过时 | 检查点尚未处理时交给 `ce-compound`，由它选最小持久化方式；刷新用 `mode:refresh` 或已注册别名。未解决的问题不是经验条目。 |
| 文档冲突、旧资料混杂、完成或中断 | 分别用 `project-governance check`、`migrate`、`close`。普通完成不另写永久报告。 |
| 同一项目新会话 | 从状态定位原计划，核对实际代码、Git、证据，继续未完成单元。需要可移交的上下文时查 `ce-handoff`。 |

阶段切换时读取 [会话阶段边界](./PHASE-BOUNDARIES.md)。既有 CE 控制器继续负责运行恢复、检查点和凭据，不将其折叠成一条状态摘要。

## 给建议或执行移交

只咨询时回复当前阶段、实际调用方式、依据、输入、完成标准和后续步骤；存在真实分叉才给备选。保持只读。

用户明确要求执行时，本轮使用宿主的 Skill 调用机制移交给**实际已注册**的目标；没有嵌套调用机制时，按当前宿主的加载规则读取目标正文，以该 Skill 的角色执行其流程。传入实际路径、约束、已定决定和证据。若宿主必须用户显式选择或实际无可调用入口，明确阻点及正确的调用方式，不把打印命令说成已经执行。不要在 shell 执行宿主斜杠命令。
