# 下一个工作交接

仅在当前管道完成或永久停止后，在 LFG 关闭时使用此功能。其目的是为单独规划的区域提供连续性，而无需默默地扩展已完成的计划或当前会话。

## 确定报价是否合理

从 LFG 步骤 1 中保留的规范计划路径开始。找到带有语义角色 `work-relationships` 的产品合同部分：

- Markdown：`<!-- ce-section: work-relationships -->`
- HTML：`data-ce-section="work-relationships"`

可见标题不是本协议的一部分。对于较旧的未标记计划，仅当产品合同部分明确命名该计划涵盖的区域、打算单独规划的一个或多个未来区域以及它们之间的关系时，才使用语义回退。不要从确切的标题、非目标的通用列表或类似路线图的愿望清单中推断资格。如果该部分的含义不明确，请不要提出建议。

仅当已完成的工作明确是一大堆单独计划的工作的一部分，并且至少有一个未来领域尚未计划时，报价才有必要。排除已经规划、完成、纳入刚刚完成的工作或不再得到当前证据支持的领域。剩余实施、审核、PR或合并任务属于当前运行的剩余运输工作；它不是下一个集思广益的候选者，并且本身不会抑制有效的未来区域报价。

## 推荐下一个区域

对剩下的候选人进行推理，而不是抢先一步。根据计划和管道了解到的情况，优先选择以下区域：

1. 具有明确的用户或计划优先级；
2. 现在可以进行有意义的头脑风暴；
3. 由已完成的工作启用；
4. 解锁最下游的工作；
5. 减少基本的不确定性；或者
6. 尤其受益于新的实施知识。

这些是判断标准，而不是评分系统。不要根据文档顺序、明显的易用性、措辞相似性或计划不支持的依赖性来选择。在提供候选人之前，根据当前的交付结果重新检查候选人。

- **一位合理的获胜者：** 说出它的名称并给出最短的具体原因。
- **真正的平局：**说目前的证据并不能证明在平局区域之间进行选择是合理的。提供以选择为中心的交接，其下一次会议将决定对哪个连贯的领域进行集思广益。
- **没有准备好的候选人：**不提供报价。

## 提供，然后停止

将报价放在 LFG 的 `<promise>DONE</promise>` 之前。保持非阻塞并且暂时不要调用 `ce-handoff`。

对于获胜者，请在自然散文中使用这种形状：

> 最清晰的下一个区域是**<area>**，因为<reason>。如果你想继续
> 在新的代理会议中，我可以为头脑风暴创建一个`ce-handoff`。

对于真正的平局，命名平局区域并提供新的会话切换，重点是选择下一个一致区域。管道仍然以 DONE 承诺结束；该报价是可选的连续性，而不是另一个垃圾填埋气步骤。

## 如果用户稍后接受

仅在明确接受后，才根据主持人的可用技能列表解决`ce-handoff`，并使用紧凑的、标记为下一步工作的简报调用`create`。 LFG 拥有推荐：它已经选择了，所以不要要求 `ce-handoff` 重新发现或排名候选人。包括：

- **下一次会议目标：**集思广益，讨论一个连贯的下一个领域，并制定一个仅满足需求的统一计划。
- **推荐区域：**获胜者，或者会议必须选择的并列候选人。
- **下一步为何：** 基于证据的选择理由。
- **权威的先前计划：** 相对于仓库的规范计划路径。
- **与已完成工作的关系：** 明确的依赖、启用、共享或独立关系。
- **实际交付状态：** 当前运行的交付步骤中已完成的内容和剩余的内容，例如已实施、PR 打开、CI 已决定或未合并。
- **结转决策：**仅限制下一个领域的先前决策。
- **要重新验证的假设：**新的头脑风暴不得继承已确定的临时关系或事实。
- **未选择的其他候选者：** 每个备选方案以及未选择的原因（当该背景阻止重复选择工作时）。
- **产物边界：**为下一个区域创建单独的仅需求统一计划，引用先前的计划，并且不要扩展或编辑先前的计划。

保持简短，指向文件而不是复制它们。请勿将之前的产品合同粘贴到其中；该计划仍然具有权威性，并且交接解释了下届会议需要决定什么。
