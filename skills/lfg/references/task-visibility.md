# 任务可见性、叙述、验证和完成

在步骤 1 之前，使用平台的任务跟踪功能（如果可用）来发布剩余管道的简短阶段级视图。从 LFG 步骤的对用户有意义的结果中得出它，而不是镜像所有十个步骤或暴露内部检查。在调用子技能之前，替换或清除 LFG 的视图，以便只有子技能的任务表面可见；返回后，在调用下一个子级之前重新创建或刷新 LFG 的剩余管道工作。仅当实际满足条件时才添加条件步骤。如果没有可用的任务跟踪功能，请正常继续，而不在聊天中模拟任务列表。

## 聊天旁白

在聊天中讲述跑步的移动过程。旁白是聊天散文，绝不是上面任务表面上的条目。输入每个步骤的一行命名该步骤及其应产生的内容；返回时的一行命名了它实际生成的内容（计划路径、返回状态、应用的修复、PR URL）。最后进行一个独立的回顾：构建了什么、如何验证以及通过什么方法、交付了什么以及任何剩余的发现。将其与`references/shipping.md`定义的结束行一起打印，这样只看到最终消息的读者就可以了解完整的情况。

当运行在完成之前停止时，它的最终消息并不是重述，因为只看到最终消息的读者一定不会将其误认为是已完成的工作。打开带有停止本身的消息：说明运行停止了，在哪一步停止了，什么阻止了它，以及用户必须做出的决定。首先提供带有您的建议的选项，当存在 PR 时，提供 PR 链接。之后，回顾一下所做的事情以及剩下的事情，并将您引用的任何子技能的回报放在开头下方。然后结束跑步。不要通过提问工具提问或等待答复；消息本身就把决定权交给了。

## 验证请求是否允许

调用 `lfg` 是用户提前给予的批准，用于验证此更改所需：浏览器测试、模拟器或设备、屏幕截图、运行应用程序或开发服务器以及该应用程序上的计算机使用。当项目说明说在其中一项之前询问用户或将测试留给用户时，则表示已经获得批准，因此无需询问即可运行验证。这遵循指令而不是覆盖它，因为用户在调用 `lfg` 时进行了回答。停下来询问无人回答的运行，以及跳过检查的运行会丢弃更改有效的证据。这适用于每个步骤，包括子技能运行的检查，例如 `ce-work` 的验证和步骤 8 的浏览器测试。

批准仅取代首先询问或将测试留给用户的请求。关于如何测试的项目规则仍然适用，因此请使用命令、夹具、数据，或检查它们的名称。批准仅涵盖此更改所需的验证。它不会扩展到生产系统、真实账户或其数据、删除数据或 `lfg` 已经做的事情之外的任何其他事情。它永远不会为您回答宿主或系统批准提示。

批准仍然可以被拒绝。它涵盖将决定或步骤交给用户的指令，例如“先询问”或“将测试留给用户”。它不包括禁止该方法的指令，无论谁运行该方法，例如“永远不要在此存储库中运行浏览器测试”；将其视为拒绝。一些主机还遵循该技能的项目或用户说明，并且工具或系统批准提示可以说“不”。当拒绝在没有所需证明的情况下留下更改时，运行将在该步骤停止并且不会报告“完成”。使用上面的停止消息：命名拒绝验证的指令或提示，并建议让它运行的内容，例如批准它或放宽该指令。由于其他原因（例如缺少工具）而无法运行的方法并不属于拒绝。忽略该方法，在回顾中说明它没有运行以及原因，然后继续。

## 完成纪律

仅在实际运行并返回后报告步骤已完成。描述一个步骤会做什么，或者接下来会发生什么，并不是在做；而是在做。在同一回合中调用它。子技能内联运行，当它返回时，没有任何东西可以恢复。它的返回结束了子进程，而不是运行：在写入或读取它之后，继续同一回合中的下一个编号步骤。不要在 `<promise>DONE</promise>` 或明确的 GATE 停止点名阻挡者之前结束回合。仅仅描述工作，或者在规定的跳过条件之外跳过的步骤，会使 DONE 为假。
