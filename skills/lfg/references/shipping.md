# 运输（垃圾填埋气步骤 9–11）

运输步骤是运行的最后阶段：提交、推送、PR、CI 和结束。 LFG 的 SKILL.md 定义了交付前置条件（`git remote` 检查）和两个调用字符串。该文件定义了其他所有内容：运行哪个切换、LFG 传递给它什么、它对结果做什么以及运行如何结束。

## 步骤 9 — 项目定义的流程可以取代默认的移交

目标是剩余的已提交工作，并且在交付前置条件允许的情况下，将其推送到您持有其 URL 的开放 PR 中。首先检查下面的本地分支，即使步骤 5 没有进行推送。对于远程切换，将未触及的预工作路径传递为 `exclude:<paths>`；如果项目定义的流程无法遵守它们，请改用默认的本机切换。

项目的活动指令可以命名该切换的过程：指定的技能或命令、堆叠工具或记录的步骤。提交或 PR-标题约定不算数，因为默认值已经遵循它们，并且单独的技能目录并不是指令。当命名此类流程时，请使用下面的相同计划路径和上下文（而不是默认值）以非交互方式运行它。仅当工作被推送并且您持有包含该工作的打开 PR 的 URL（打开的进程之一或分支已存在的 PR）时，才会完成此操作。如果它无法无头运行、不可用或未达到该状态，则以 **阻止** 命名该进程而停止。不要落入默认值或步骤 10。

## 第 9 步 — LFG 传递给默认值的内容

将记录的计划路径从步骤 1 传递到 `ce-commit-push-pr` 调用，以及步骤 2 中任何已处理和标记的 `settled_decision_conflicts` 条目，因此 PR 主体可以包含其已解决的决策出处行及其在标记的冲突下进行工作的注释。在一次性语句中，没有计划也没有简介：将语句作为 PR-描述上下文传递。在缺陷路线上，没有计划，也没有简介：将调试返回的 `root_cause` 和 `issue_of_record` 作为 PR 描述上下文传递，每个 `references/debug-return.md`，因此 PR 主体携带诊断并链接或关闭票证。还传递步骤 6 的 `## Unapplied review findings` 部分（如果存在）作为 PR 描述上下文，逐字呈现为专用部分。该部分记录了未应用的发现；在没有它的情况下打开PR的运行已经丢失了它们。检查计划的执行配置文件是否作为一个 PR 或多个进行交付。当它作为多个交付时，要求一个堆栈并命名其层：每个 PR 组一个，按合并顺序从下到上，每个都有其单位，并且当其 `Waits on:` 行命名必须首先运行的部署时，将依赖项部署为 PR 描述上下文。 `ce-commit-push-pr`在此请求中从土地意图中选择堆栈的PR 看护姿势，因此合并授权在这里决定。当用户同意合并时，请包含土地意图，以便它移交 `posture:stack-land`。当任何层带有部署依赖项时，请忽略土地意图，以便它交出`posture:stack-ready`，因为没有技能观察部署；然后，收尾会列出用户在合并之前必须确认其部署的每个层。然后应用步骤 10 中的堆栈切换。

由于 `mode:pipeline` 令牌，这会以非交互方式提交所有剩余的更改、推送分支并打开拉取请求。如果它在 PR URL 之后打印 `New concepts:` 预告片，请记录步骤 11 的概念名称。如果分支已存在 PR（检查`gh pr view --json number,url,state 2>/dev/null`），则跳过 PR 创建，但仍提交并推送任何未提交的更改。管道模式默认情况下会保留现有的PR主体，因此上面的描述上下文将会丢失；推送后，在具有相同上下文的 PR 上以描述更新模式再次调用 `ce-commit-push-pr mode:pipeline`，因此记录到达审查者时不会出现确认提示。

**根据交付前置条件，当没有配置远程或传出工作未提供或未知时，请勿调用 `ce-commit-push-pr` 或项目定义的交付流程。** 默认的提交步骤无条件推送 (`git push -u origin HEAD`)，因此文字调用仍然会遇到不可能的推送。相反，按名称提交此运行更改的文件（工作源的文件、审阅修复以及任何捕获的学习内容），并完全跳过推送和 PR 创建。从不`git add -A`：运行前已经脏的文件，或者缺陷路由的`pre_fix_scope`列表之一，保持未提交状态并在报告中命名。

## 第 10 步——第 9 步的堆栈切换

如果步骤 9 保持发布，则完全跳过步骤 10，包括在先前具有 PR 的分支上。说明哪些内容保留在本地以及原因。

如果步骤 9 的 `ce-commit-push-pr` 完成了堆栈模式提交，并在 **底部打开的非草稿** PR 上与 `posture:stack-ready` 或 `posture:stack-land` 交接了 `ce-babysit-pr`：

- **不要**在当前分支 URL 上启动第二个裸 `mode:pipeline` PR 看护。第二次运行可以用仅监视当前 PR 的运行替换堆栈感知的运行，或者监视堆栈的错误层。
- 当反映已完成的管道停止时，首选已从该切换返回的结构化结果。
- 如果第 9 步仅确认babysit **started**（或没有可用的结构化结果），请重新调用 `ce-babysit-pr mode:pipeline <bottom-pr-url> posture:<same>` 并等待其管道完成 - 切勿将“started”视为完成。
- 记录步骤 11 面向用户的简历行的底部 PR URL 和姿势。
- 收集 `{ status, fixes_applied, residuals }` 并继续执行步骤 11。

## 第 10 步 — 默认PR 看护

否则在当前打开的PR上调用`ce-babysit-pr mode:pipeline <pr-url>`。它运行有界管道循环：它监视 CI，通过 `ce-debug mode:pipeline` 修复真实（收敛）故障，而不会削弱、跳过或嘲笑断言，解决通过 `ce-resolve-pr-feedback mode:pipeline` 到达的任何评审意见，并在 CI 决定或其预算（默认 3 轮修复）达到时停止。这取代了 LFG 以前的手卷CI环；不要在这里重新实现CI-观看。

每当存在打开的 PR 时无条件调用它**并且**步骤 9 尚未移交堆栈PR 看护。这包括在常设`auto_babysit: false`下运行：该设置选择退出打开PR后移交的开放式手表，而不是产生管道“CI决定”结果的有界循环。 CI 看起来可能干净的运行并不是跳过PR 看护并亲自投票 `gh pr checks` 的理由。瞬间绿色 CI 并不是此步骤的目标：babysit 还解决了 PR 整个生命周期中的审核评论，因此在咨询检查（例如 Bugbot）仍待处理或评论未处理时通过检查并没有“完成”，并且永远不会替代调用。

收集其结构化结果（`{ status, fixes_applied, residuals }`）。

合并是用户的，除非他们为这次运行授予了合并权限。当他们这样做时，以 `ce-babysit-pr` 接受：`posture:stack-land` 的形式传递授权，在第 9 步中决定的托管堆栈上。单个 PR 授权目前没有管道载体，因此在该路径上不要合并自己；在结案中说，这笔赠款无法进行，合并仍然属于他们。

## 第 10 步——公共结果门

此检查适用于产生结果的任何切换。保持其返回的 `needs-human` 残差及其携带的每个字段不变。在缺陷路由上，添加`ce-debug`的`fixed`返回携带的`residuals`，同样不变。在完成之前，在`## Needs your decision`下呈现完整的集合，包括每个残差引用的反馈、调查、决策原因、选项和权衡、建议（如果有）以及每个开放线程链接。非空集意味着运行将决策交给用户；它永远不会成功完成。通用计数或 PR 链接不算作传递集合。无法修复的 CI 仍然属于PR 看护的运行报告注释，而不是 PR-body 部分。

## 第 11 步 — 结束

下面的一切都发生在 LFG 输出 `<promise>DONE</promise>` 之前。写下结尾、`## Needs your decision`框架，以及通过`ce-noslop`技能向用户讲述的任何进度；剩余条目本身是逐字呈现的。

### 呈现用户可运行的调用

对于下面的两次切换，默认为 `/ce-explain <name>` / `/ce-babysit-pr <pr-url>`。仅当活动主机为 Codex 或明确记录以美元为前缀的技能调用时，才使用 `$ce-explain <name>` / `$ce-babysit-pr <pr-url>`。仅将调用呈现为内联代码并仅输出一种形式。

### New concepts

如果步骤 9 录制了 `New concepts:` 预告片，则首先回显每个概念一行：`New concept introduced: <name> — run <rendered ce-explain invocation> to go deeper.`

### 开放PR

如果存在打开的PR，则添加一行将用户指向交互式监视以进行合并（管道模式停止于“CI已决定”，而不是“已合并”）：`PR 已进入后续流程；如需看护到审查完成和合并，请运行 <rendered ce-babysit-pr invocation>。`

当步骤 9/10 使用堆栈切换时，使用相同的 `posture:stack-ready` 或 `posture:stack-land` 令牌呈现对 **底部开放非草稿** PR URL 的调用 — 绝不是会取代堆栈范围的裸露当前分支 URL。

### 可选的下一份工作报价

在缺陷路线上没有计划：不提供下一步工作。一次性声明也没有计划：不提供下一份工作机会。否则检查步骤 1 中记录的计划中的语义角色`work-relationships`。当该角色存在时，或者当较旧的未标记产品合同出现命名该计划拥有的区域以及未来单独计划的区域及其关系时，加载`references/next-work-handoff.md`。该引用文档定义了谨慎的遗留语义回退、如何选择候选人以及选择加入要约的措辞方式。不要匹配精确的可见标题，将普通的非目标视为未来的工作，或者在用户明确接受要约之前调用`ce-handoff`。如果这两个语义信号都不存在，则不加载引用文档并且不提供下一步工作。

然后输出 DONE 承诺。
