# 工作流和文档职责

按项目实际路径与约定落地；保留项目现有代码、依赖、命令和审查规则。

- 从状态文件定位当前计划，结合 Git 确认下一个未完成的单元、已有实现和可复用证据。CE 负责运行 ID、收据和恢复状态；状态文件是索引，不是第二套任务跟踪器。
- 明确的小改直接完成。术语不清用领域访谈，产品或方案不清用研讨；择一补足事实，把确定的取舍交给 CE 规划。已有计划则继续实施；具体缺陷先复现、定位根因，再做能区分问题的回归验证。
- 规划、诊断或研究前按需读领域词表、ADR、研究及相关经验。版本或条件变化时复验旧结果；用项目真实入口验证，区分实际结果、预期和未验证事项。
- 范围、验收与实施单元写进 CE 计划；长期取舍归 ADR；确认术语归词表；实验结论、假设、反例和过时结果归研究。可复用的经验由 CE Compound 判断如何留下。一项事实只有一处权威；其他位置用引用。
- 暂停或结束重要任务时，做治理收尾并更新状态。将最终差异交回 CE 原生验证、审查与 Git 交付。不清理唯一证据；原始或私有材料保存在已忽略的适当位置。
