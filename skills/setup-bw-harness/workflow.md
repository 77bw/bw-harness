# Workflow and document ownership

Adapt these rules to the project’s actual paths and language. The existing project owns its code, dependencies, commands and review conventions.

- On resumption read status and its current plan; confirm the next unfinished unit against Git, the implementation and applicable evidence. CE run IDs, receipts and recovery state belong to CE; status is an index, not a second task tracker.
- A clear small change can proceed directly. A real domain ambiguity belongs in a domain interview; an unresolved technical/product choice may call for brainstorming. Choose one, carry settled decisions to CE planning, and continue an existing plan in place. A defect starts with reproduction and a discriminating check.
- Before substantive planning, diagnosis or research, search the relevant domain glossary/ADRs, topic research, and past solutions. Recheck old results if versions or conditions changed. Use project-native validation; distinguish observed results from expectations.
- Scope and acceptance belong to the CE plan; lasting tradeoffs to ADRs; confirmed vocabulary to the glossary; tested findings, hypotheses, counterexamples and stale results to topic research. Reusable corrections follow CE Compound; keep one authority per fact and link to it.
- When pausing or finishing a material task, reconcile evidence and changed knowledge with governance close, update the current status in place and return the final changes to native CE verification and Git delivery. Preserve unique evidence; use ignored local scratch for raw or private artifacts.
