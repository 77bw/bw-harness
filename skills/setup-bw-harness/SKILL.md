# 接入 BW Harness

派生自 Matt Pocock 的 setup-matt-pocock-skills，遵循 MIT；固定来源与差异见包的锁文件。沿用「探索 → 展示发现与选项 → 确认实质变更 → 按模板合并 → 验证」的流程。保留项目原有代码、测试、工具和用户约定。

## 0. 确定目标和模式

以用户指定目录为准，默认当前目录；模板以**实际加载的 `SKILL.md` 所在目录**为锚，CE 资源使用当前包内副本。必要资源缺失或同名来源无法确认时，指出受影响步骤并暂停。

- 显式调用默认接入：空目录与已有项目共用流程。只改工作约定与文档，不生成应用代码。仅预览时，在第一次写入前返回。
- `update`：原位更新旧 BW 规则，保留用户独立约定。
- `check`：只读执行探索和诊断。不得初始化 Git、安装、修复、更新状态或运行产生写入的检查。
- `migrate`：定位旧资料后交给已加载的 `project-governance migrate`，setup 不搬历史知识。
- 若只是旧生成请求（如 `new --api`），说明旧生成器已移除，不执行接入、不写文件、不安装。

核对目标不是分发包目录或意外命中的父仓库。若处于更大 Git 根下，先明确仓库边界再接入。日常开发不会隐式执行 setup。

## 1. 探索现有项目

- 核对 Git 根、工作树、分支、HEAD、远端及已暂存、未暂存、未跟踪改动。报告远端时隐去凭据和查询参数。
- 追到实际生效的项目指令；定位 `## Agent skills` 或旧 BW 块。核对 include 和符号链接，不向范围外的目标写入。
- 仅从 `.compound-engineering/config.yaml` 读取 `docs_root`，默认 `docs`。核查实际路径和目录边界；非法值先指出，暂停文档写入。本地覆盖不修正共享配置。必要时在项目中用包内 [CE 健康检查](../ce-setup/scripts/check-health)，不预热缓存。
- 查实际 domain、GLOSSARY 或 GLOSSARY-MAP、旧 CONTEXT/MAP 或 CONCEPTS、ADR、工作流说明、任务跟踪、状态、活动计划、研究和经验。领域布局可与 CE 根不同；无真实领域边界则采用单上下文，无可选文档属正常。
- 从 README、CI、清单和脚本确定真实验证入口；核对当前 Skill 来源与能力，区分可选工具缺失和接入阻塞。不安装无关依赖。

## 2. 展示发现并对齐选择

列出 **已有、缺少、冲突、未知** 及依据；展示拟新增、修改、保留的文件和 Git 边界。优先给出推荐，一次解决一个会改变结果的决定。已明确采用标准接入的非冲突步骤不重复确认；实质冲突不静默覆盖。

只保留一个主要项目指令入口。已有 include 或内部链接就沿用；两份独立规则冲突先征询；全无时优先用 `AGENTS.md`，除非项目或用户已指定其他入口。确认实际领域布局和文档根。默认 **CE 计划是实施正文**，已有外部任务跟踪器只负责关联和协调；有远端不代表同意同步工作项。不初始化标签。

`check` 到此返回问题位置、依据和下一步。只预览则返回拟变更。其他情况下仅在已明确的范围内继续。

## 3. 读取随包模板并合并

先读 [领域模板](./domain.md)、[工作流模板](./workflow.md)、[状态模板](./status.md)、[忽略规则](./gitignore.md)。确需独立任务跟踪说明时再读 [本地计划](./issue-tracker-local.md) 或 [GitHub 跟踪](./issue-tracker-github.md)；其他跟踪器依项目实际规则。模板不是项目事实。

在解析出的根下创建或合并 `agents/domain.md`、`agents/workflow.md` 和 `status.md`。Matt 已使用独立领域入口时更新实际文件，不另造树。`agents/issue-tracker.md` 按需创建。按「缺项新增、同义保留、无冲突原位合并、有冲突先展示」执行。保留注释、引用、用户改动和并行工作。只有确知出自旧 BW 的内容，才移除其强制 Python 布局/工具、仅本地 Git、强制 `return-to-caller` 与旧生成命令；同类用户自主规则不替换。

已有 `## Agent skills` 块则原位更新，不追加副本。按实际项目路径落以下入口；标题保留原拼写，供已有规则定位：

    ## Agent skills
    - 领域术语和 ADR：做相关设计或诊断前读 docs/agents/domain.md。
    - 工作流与文档职责：选路、维护知识或收尾时读 docs/agents/workflow.md。
    - 从 docs/status.md 和其中所指的活动计划恢复任务。
    - docs/solutions/ 按类别与 YAML 元数据保存已验证经验，实施或排错时按需检索。
    - 计划与 Git 交付依 CE 原生流程和项目现有配置。

需创建共享 CE 配置时读包内 [配置模板](../ce-setup/references/config-template.yaml)，保留已有键与注释。知识库入口和自动捕获指令按 [CE 仓库修复步骤](../ce-setup/references/repo-fixes.md) 第 9 步处理；知识库已跟踪或项目接受该入口时，使用包内 [自动捕获指令](../ce-setup/assets/compounding-directive.md) 的 `Run automatically` 版本。已有等价指令则保留，冲突先核对。不要复制出第二个触发器；不要运行整套 CE 初始化或启动可选标准访谈。无真实内容则不创建空词表、ADR、计划、研究或经验。

## 4. 检查 Git 与实际效果

只有目标确为独立项目且没有仓库时初始化 Git。已有仓库保留历史、远端、身份和用户改动。按模板合并忽略规则，验证代表性路径和例外，识别已跟踪风险，不把已忽略误报为已取消跟踪。需要初始提交且在约定范围内时，检查身份、HEAD 和索引，只暂存指定的基线文件；不纳入先前暂存的工作，不改全局配置，不创建未知远端。

复核生效入口和引用、实际配置、状态及变更差异（包括新文件）；确认再次接入会更新同一块而非重复添加。按实际项目入口运行范围内的适用检查，报告真实命令和结果。无业务测试时说明，不安装固定工具链，不通过改源码或删证据来消除检查问题。

## 5. 返回

列出 **已创建／已更新／已保留／阻塞／检查／下一步**，包含真实路径、入口作用、Git 状态、待迁移资料和当前宿主可以执行的下一步。区分接入、业务验证和远端交付。不另创建 setup 报告。
