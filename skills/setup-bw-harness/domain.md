# 域文档

在探索代码库时，工程技能应如何使用此存储库的域文档。调整这些规则时请使用项目的实际位置。

## 在探索之前，请阅读这些

- **`GLOSSARY.md`** 位于存储库根目录，或者
- **`GLOSSARY-MAP.md`** 位于存储库根目录（如果存在）：它指向每个上下文一个术语表。阅读与主题相关的每一篇。
- **ADR**：阅读涉及您将要工作的领域的决策。使用项目的现有决策目录，以及在多上下文存储库中映射域的范围决策。默认的单上下文布局是根词汇表 + `docs/adr/`；多个域可以各自拥有自己的术语表和决策，而无需共享源布局。

如果这些文件中的任何一个不存在，**默默地继续**。当术语或决策实际得到解决时，领域建模会延迟创建它们。不要留下空术语表或占位符决定。

## 使用词汇表的词汇

在计划、假设、测试或评审中命名领域概念时，请使用规范术语并尊重其消除歧义的范围并避免使用同义词。缺失的单词可能是发明的同义词或真实的建模问题。使用领域证据来区分它们。 CONTEXT、CONTEXT-MAP 和 CONCEPTS 是分类的历史输入；两个相互冲突的定义不会同时成为当前的定义。

要规划或调试研究主题，请参阅其研究笔记和相关解决方案。实验结果本身并不是领域定义。保留研究中的条件、负面结果和未知因素。

## 标记ADR冲突

如果您的输出与现有的 ADR 相矛盾，请明确地显示它，而不是默默地覆盖：

> 矛盾ADR-0007（事件源订单）；新观察到的约束是……。
