# 接管

当用户询问时，继续别人打开的PR替换PR：通常是因为babysit无法推送到贡献者的分支，或者贡献者已经停止响应。原始贡献者保留他们的信用，并且原始 PR 保持打开状态，除非用户允许关闭它。

**结果：** 一个处于监视状态的开放替换PR，其历史记录包含其作者的原始提交，以及作为单独提交的babysit自己的更改。 **安全故障方向：**当无法获取来源或无法携带信用时，请停止并报告，而不是打开未信用的替代品。

仅在交互式运行中根据用户的请求接管，并且仅从开源PR 接管。

1. **首先评估。** 在源 PR 上运行`references/intake.md` 中的评估和判决。关闭判决以该证据结束了收购。更新和返工在这里继续而不是停止；通过返工，替换品将进行所描述的返工。
2. **来自源的分支。** 从从 `refs/pull/<N>/head` 获取的源头 OID 创建替换分支，而不是本地引用，因此每个原始提交都会保留其作者。将您自己的更改作为单独的提交进行。
3. **在推送之前对其进行更新**：将替换分支重新设置到新的基础上，并应用 `references/intake.md` 中已验证更新的步骤 2-4 中的比较规则。目前还没有其他人拥有此分支，因此堆栈、dependent-PR 和租赁规则不适用。接管中的任何内容都不会触及源分支。
4. 自开始以来，**重新检查源**以获取新的提交或反馈。在继续之前，以评估阅读原始系列的方式阅读每个新提交，并将仍然适用于您自己的更改的反馈纳入其中。记录您完成的源头 SHA。
5. **当源是分叉时，或者当任何进行的提交更改CI工作流程或代码CI运行时，请在第一次推送之前确认。**将替换推送到此存储库会使用存储库的秘密运行该代码，而不会使用GitHub的分叉-PR批准门，因此只有在用户确认后才进行推送。
6. **通过 `ce-commit-push-pr mode:pipeline` 打开替换**，传递源 PR URL 和原始提交作者（来自源 PR 的提交）作为描述的信用上下文。管道模式会跳过 `ce-commit-push-pr` 自己的移交以进行PR 看护，因此此运行仍然是唯一的观察者。替换目标为源PR的基础分支并保持其草稿状态；如果以其他方式打开，请在观看前更正它（`gh pr edit "<new-N>" --repo "<[host/]owner/repo>" --base "<source-baseRefName>"`，`gh pr ready "<new-N>" --repo "<[host/]owner/repo>" --undo`）。
7. **观察替换。** 当此运行已拍摄第一个快照（观察中请求接管）时，停止该观察程序并继续对新的 PR 进行调用，就像堆栈转换 (`references/setup.md`) 的方式：`--continue-invocation` 以及记录的调用 ID、开始时间和预算以及重新声明的状态。否则，尚不存在调用：按照 `references/tick.md` 的描述启动新的 PR 的第一个快照。

未经用户明确许可，切勿关闭源PR。该报告将来源命名为PR，交接时的头 SHA，替换者PR，以及信用如何进行。
