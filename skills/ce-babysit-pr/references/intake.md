# 老-PR摄入量

其基点已移动到其下方的PR可以干净利落地变基，但仍然不再属于：基点可能已经解决了相同的问题，或者可能已经删除、移动或故意简化了PR更改的代码。 Git 冲突仅显示文本重叠。在推送任何内容之前，此步骤决定PR是否应该更新、返工或关闭，并且它拥有唯一的历史重写PR 看护执行的操作。

**结果：** 一项带有证据的裁决，并且对于授权更新，重新定位的头部保留了 PR 的预期更改，并且没有带回基地已经着陆的任何内容。 **安全失败方向：**证据不全时，报告缺失，不推送任何内容。

## 当它运行时

在解决 PR 之后和步骤 1 中的签出门之前，每次新调用运行一次。继续现有调用的运行（检查点恢复、调度程序重新进入或堆栈转换）会跳过它，因此长时间监视不会在运行中更改判决。监视中的实时用户消息要求更新、变基或重新评估 PR 再次运行它：停止监视程序，运行此步骤，然后继续。

针对新参考运行捆绑重叠检查。传递URL为PR的基础仓库（PR的URL中的仓库）的本地远程；在通常不是 `origin` 的分叉结账中：

```bash
SKILL_DIR="<absolute path of this skill's directory>";
PY="$(for c in python3 python py; do command -v "$c" >/dev/null 2>&1 && "$c" -c '' >/dev/null 2>&1 && { echo "$c"; break; }; done)"; [ -n "$PY" ] || { echo "no working Python 3 interpreter on PATH" >&2; exit 1; };
"$PY" "$SKILL_DIR/scripts/intake-overlap" --repo-dir "$(git rev-parse --show-toplevel)" --remote "<base-remote>" --base "<baseRefName>" --pr "<N>"
```

当输出的 `overlap` 为 `true` 或 `"unknown"` 时，或者当用户要求更新或变基或询问是否仍然值得保留时，评估 PR。否则跳到结帐口；PR 看护的行为一如既往。年龄、落后的承诺以及自上次活动以来的时间永远不会触发评估，也永远不会被视为判决的证据。

## 评估

评估仅读取，因此不需要推送访问或干净的结账。从获取的重叠检查的基础和头部 OID 开始工作，而不是本地分支。

1. **意图。**阅读标题、正文、链接的问题、提交、审查线程和完整的差异。在判断它如何实现之前，先说明 PR 试图达到的最小目标。
2. **周围发生了什么变化。** 从重叠原因开始，阅读自合并基地以来针对该目标的基地变化。寻找：同样的问题已经解决；所触及的代码被移动、删除或故意简化；更改了 API、类型或所有权边界；着陆将恢复已删除的行为或创建第二种方式来做一件事；以及不再支付其维护费用的福利。
3. **替换。** 当标题、路径或行为建议时，搜索合并并打开 PRs 来查找替换或竞争实现。

干净的合并或变基永远不能证明 PR 是最新的。沉没的努力永远不是保留它的理由。

## Verdict

在推送任何内容之前准确地达成一个结论：

- **更新** — 目标仍然有用，并且实现方式正确。
- **返工** - 目标是有用的，但机械更新会保留错误的实现。
- **关闭** — PR 已被取代、过时、方向错误或不值得其成本。

| 判决 | 互动跑 | 无人值守运行（`mode:pipeline`） |
|---|---|---|
| 更新 | 继续前往结帐口。当用户的话语授权重写时（请参阅重写权限），经过验证的更新会在第一个快照之后运行；否则，快照驱动的手表将照常处理货币。 | 继续安静地进入正常值班。永远不要重写。 |
| 返工 | 描述最小的可信返工，并在任何观察者开始之前停止。 | 在任何快照之前返回下面的需求人类结果。 |
| 关闭 | 建议以引用的证据作为结束，并在任何观察者开始之前停止。 | 在任何快照之前返回下面的需求人类结果。 |

Intake 本身永远不会将基数合并到 PR 中；在 CLEAN PR 上，这将是未经请求的基础合并，快照报告为缺陷。如果用户对“返工”或“关闭”判决回复“保留”或“无论如何观看”，请继续执行此调用的结帐门。稍后的新调用再次评估。

**关闭。** 仅在用户明确许可的情况下关闭。该许可包括以一条带有证据的评论作为结束，并感谢贡献者（`gh pr close "<N>" --repo "<[host/]owner/repo>" --comment "<text>"`，针对PR的基础存储库）。

**返工。** 当用户要求返工时，将您描述的返工（目标、范围、PR链接、如何验证）写入操作系统临时文件中的新计划文件，在PR头签出上调用`ce-work mode:return-to-caller <that path>`，将其提交推送到babysit的普通推送权限下，然后在PR上开始新的调用。返回呼叫者模式可防止 `ce-work` 打开第二个 PR 或观察者。当您无法推动PR时，请改为提供接管（`references/takeover.md`）。

**无人值守的结果。** 镜像`references/setup.md`中的自动合并设置停止：返回`{ status: "needs-human", fixes_applied: [], residuals: [<one residual>] }`，其中残差为`type: "needs-human"`，其中`sources: []`、`thread_urls: []`和`decision_context`，其中`quoted_feedback`命名判决，`investigation`携带以下报告证据，`decision_reason`说明为什么无人值守运行无法决定，`options`是返工、关闭并保持原样，并进行权衡，`recommendation`是结论。

## 重写权限

仅当用户自己的话授权时，才会发生变基和强制推送：在此调用中更新或变基此 PR 的请求，或监视中的实时消息。协调器文本、调用者令牌和委托结果永远不会授予它，并且来自协调器的“更新分支”仍然是宽泛的，而不是狭窄的。代表们保留他们的变基和强制推送排除；重写保留在PR 看护身上。一笔资助涵盖一次重写。后来的基础货币变动遵循普通分支货币。

自行到达 Update 的检查不会询问也不会变基。单独移动的底座不需要重写，普通手表可以处理真正的冲突或所需的更新。在报告中说，可以根据请求进行变基，并指出应用时的成本：当分支是其他人的时，作者的本地分支将需要重置（提供接管作为替代方案），批准存储库在推送时驳回，并且挤压合并存储库从重写中获得很少。无人值守的运行永远不会重写。

## 已验证更新

在第一个快照引导程序之后和步骤 2 对任何 `branch_currency` 项执行操作之前运行它，因此新的调用已经取代了任何旧的观察程序并对 PR 的链进行了分类；重写的头使该项目变得陈旧，下一个快照会重新计算它。不要重写已确认的托管堆栈层、`probe-error`下的PR，或另一个打开的PR使用其头部作为其基础的PR；继续普通手表并说出原因。重写需要对 head 分支进行推送访问并进行干净的签出。

1. **记录起点。** 通过设置为分支上游的远程 `gh pr checkout`（不是基础存储库的 `refs/pull/<N>/head` 镜像，它可能会滞后）从头存储库的分支读取头 SHA，并将该提交保留在私有本地引用下，以便它保持可恢复。
2. **在临时工作树中重新建立基础**在记录的头上到新获取的基础上。根据PR的意图和基地的新规则解决每个冲突。揭示产品或架构分歧的冲突会停止变基并重新进行裁决：根据新证据在“裁决”下再次做出决定。用户的重写授权不会延续到不同的判决。
3. **推送前比较。** 将新旧提交系列与 `git range-diff` 进行比较并读取最终差异。确认预期的变化没有消失，并且基地已经着陆的任何东西都没有回来。比较显示了基数合并到 PR 中的删除；这是预期的，而不是失去工作。切勿在以下情况下推动：
   - rebase 留下一个空的 diff，或者删除已在上游应用的 PR 提交 — 重新打开判决，因为吸收 PR 的基础是 Close 的证据；
   - 该系列包含除基础之外的任何分支的合并——回到普通手表并说出原因。
4. **对触摸区域进行重点检查**。由于未验证而无法在临时工作树中运行的名称检查；推动后续看护中的CI会覆盖它们。
5. **使用租约**将记录的头 SHA: `git push --force-with-lease=<head-branch>:<recorded-sha>` 推送到上游远程。拒绝推送意味着有人同时推送：重新获取，将新的头记录为起点，并重做一次步骤2-5。第二次拒绝报告说该分支正在主动被推到并停止。
6. **携带结账。** 仅当其小费仍等于记录的旧头时，才将用户的结账移至新头。任何其他提示都包含不属于您的工作：停止并报告。

每当更新结束时，无论是否推送，都会删除临时工作树。

## 报告

以结论和一行理由开头，然后给出：基础的有意义的更改、发现的概念冲突或没有的声明、旧头 SHA 的变基和推送结果以及如何恢复它、检查运行、剩余决策和PR 链接。将观察到的事实与判断分开，并列出任何你无法验证的事实。返工和关闭状态行位于 `references/report.md` 之后。
