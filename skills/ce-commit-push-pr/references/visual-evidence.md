# 视觉变化的截图

当 PR 改变了审查者通过查看判断的内容时，正文中的屏幕截图让他们看到它，而不是从散文中想象它。当之前的图像很容易获得时显示之前和之后，只有当价格不便宜时才显示之后。丢失的屏幕截图永远不会阻止PR。

## 何时捕捉

仅当更改做出重大视觉声明时才捕获：审查者通过查看它比通过阅读它可以更快或更正确地判断呈现的 UI。例如布局、样式、屏幕文本、新的或更改的屏幕、状态或组件以及视觉错误修复。否则不要截图，也不要询问。文本输出（例如 CLI 输出、日志或 API 响应）属于代码块，而不是文本图片。

在仅描述模式下，没有可附加的 PR，因此请勿捕获。在一行中说明应用描述时可以添加屏幕截图。当正文在应用之前仍等待用户确认时，请在确认后截取屏幕截图。已经具有 `## Screenshots` 或 `## Demo` 的现有 PR 主体将保留它，因此不要再次捕获。例外情况是用户请求刷新它以及在拍摄这些图像后所做的提交改变了它们显示的内容；然后重新拍摄受影响的图像并替换它们。

当项目的说明要求在运行应用程序、打开浏览器或截取屏幕截图之前进行询问时，请遵循这些说明：在交互式运行中询问，并在 `mode:pipeline` 中用一行原因跳过。否则不问就捕获。当他们说 PR 屏幕截图去哪里时，例如从正文链接的托管页面，请将它们放在那里而不是附加它们。这些说明中声称 GitHub 无法上传并不是跳过的理由；下面的交货检查决定了这一点。

每当在没有屏幕截图的情况下发布重大视觉声明的更改时，正文都会在一行中说明原因。

## 捕捉需要什么

三者都必须持有。如果缺少任何内容，请写下验证注释 `references/compose.md` 描述并添加一行，说明未捕获屏幕截图及其原因。

- **一种传递图像的方式。** 当项目的说明指定屏幕截图的去向时，该目的地就是方式。否则，将应用主体的命令的帮助（`gh pr create --help`，或`gh pr edit --help`对于现有的PR）必须列出`--attach`标志。在拍摄任何东西之前请检查此项，因为如果没有办法，图像就无法到达 PR。
- **将图像文件保存到磁盘的浏览器。**首选当前主机内置的浏览器。否则，如果已安装，请使用`agent-browser`，并首先加载其自身的指令。切勿安装工具或引入另一个浏览器堆栈。向您显示屏幕截图但不写入文件的工具不符合资格。
- **应用程序在更改后的路线上运行。** 使用已运行的开发服务器，或项目文档之一，无需额外设置即可启动。不要仅仅为了截图而安装依赖项、配置机密或种子数据。

## 之前的图片来自哪里

使用第一个存在的源，然后停止：

1. 用户、调用者或项目工具已生成的未进行此更改的 UI 屏幕截图，例如基本与分支比较运行。
2. 未进行此更改的已部署的 UI 副本：基础分支的预览部署，或同一路由的生产 URL。
3. 没有任何。单独贴出之后的截图。

全新的UI没有以前的形象。除非用户要求，否则不要在第二个工作树中构建基本修订版或在签出中交换文件以获得一个工作树。切勿伪造之前的图像，例如通过撤消浏览器开发工具中的更改。在表格下，说明之前的图像来自哪里（提交或 URL），因为生产 URL 可能与此 PR 的基础不匹配。当更改改变了现有 UI 并且您仅发布后图像时，请在表格下方一行说明为什么没有前图像。

## 截图

- 对一对图像使用相同的路线、视口和数据状态。与全页屏幕截图相比，更喜欢视口或组件屏幕截图。 GitHub 将表格行中较短的图像垂直居中，因此一对中的两个图像应具有相同的大小。
- 将每张图片控制在 10 MB 以下，这是 GitHub 的图片上传限制。
- 默认截取桌面屏幕截图。当更改响应时添加移动对。
- 拿几张照片来证明这一说法，而不是浏览该应用程序。
- 仅拍摄静态屏幕截图。仅当用户提供时才包含视频或 GIF。
- 使用开发或种子数据。发布前查看每张图片。如果显示凭证、令牌、个人数据或带有秘密的 URL，请在不包含这些内容的情况下重新获取或删除它。切勿模糊或裁剪。
- 将图像保存在存储库外部的一个新临时目录中，文件名不包含空格。将之前提供的所有图像复制到同一目录中，因为正文通过相对于每个图像的路径引用每个图像。永远不要犯下这些错误。

## 在体内

将图像放在`## Screenshots`下，放置在`references/pr-description-writing.md`放置证据块的位置。通过相对于该目录的本地路径引用每个图像，并使用替代文本来命名它所显示的内容：

```markdown
| 前 | 后 |
|:---:|:---:|
| ![之前：设置页面](./before-settings.png) | ![之后：设置页面](./after-settings.png) |
```

对于事后屏幕截图，该表只有一个 `Preview` 列。无论哪种方式，节标题都是`## Screenshots`，因为稍后的重写仅保留`## Screenshots`和`## Demo`。 apply 步骤上传文件并将这些本地路径替换为 GitHub URL； `references/apply-and-handoff.md` 中的“通过 gh 申请”拥有这一点。
